## 2025-05-18 - Timezone-Aware O(N) getWeeklyFocus
**Learning:** Parsing and formatting dates dynamically within nested loops can be exceptionally slow, especially when done across multiple filter conditions. In `getWeeklyFocus`, evaluating 7 days meant filtering and formatting the entire dataset 7 times, yielding O(7N) parsing overhead. However, timezone correctness is easily lost if strings are truncated or sliced prematurely (e.g. `s.date.slice(0, 10)`), which causes drift in non-UTC timezones.
**Action:** Always pre-fill result structures and construct O(1) hash maps based on fully parsed and timezone-aligned keys (`format(parseISO(...), "yyyy-MM-dd")`), then iterate over datasets in a single pass (O(N)) to retain timezone-aware correctness while maximizing performance.
